EVIDENCE

Organising Work into 15 Sprints

The BrightStart team initially had one long Product Backlog containing the tasks required to plan, design and develop the English Tutoring website. After receiving feedback from the lecturer, we reorganised the work into individual sprints using Trello.

The Sprint Backlog presents the work according to the sprint in which it was planned. The tasks below summarise the project activities discussed in our planning. The original Trello board should be used to verify the exact tasks, dates and allocations.

Sprint 1 — Review the Project Brief

Focus: Understand the project and establish the team.

  • Review the project brief.
  • Form the project team.
  • Define team roles.
  • Brainstorm the business idea.

Sprint 2 — Identify the Business Opportunity

Focus: Understand the problem and research the proposed business idea.

  • Select the initial business idea.
  • Define the community context.
  • Define the problem statement.
  • Conduct market research.

Sprint 3 — Understand User Needs

Focus: Gather information and explore the initial solution.

  • Create wireframes.
  • Collect survey responses.
  • Analyse survey results.
  • Present the initial business idea.

Sprint 4 — Refine the Business Proposal

Focus: Improve the proposed business idea and prepare the project proposal.

  • Review lecturer feedback.
  • Prepare the business proposal.
  • Create the initial Product Backlog.
  • Finalise the business idea.

Sprint 5 — Assess Project Feasibility

Focus: Review the business idea and assess its feasibility.

  • Set up the Trello board.
  • Refine the business idea.
  • Complete the 5Ws.
  • Conduct a feasibility analysis.

Sprint 6 — Define the Minimum Viable Product

Focus: Identify the key requirements and features of the proposed solution.

  • Define the minimum viable product (MVP).
  • Identify stakeholders.
  • Gather system requirements.
  • Define system features.

Sprint 7 — Prioritise Project Requirements

Focus: Organise requirements and prepare for the next stage of the project.

  • Prioritise the Product Backlog.
  • Divide Product Backlog tasks into sprints.
  • Review wireframes.
  • Prepare the presentation for Ms Prima.

Sprint 8 — Set Up the Website

Focus: Establish the website structure and navigation.

  • Set up the GitHub repository.
  • Set up the project structure.
  • Design website navigation.
  • Develop the home page.

Sprint 9 — Develop Information and Registration Pages

Focus: Provide information about the tutoring service and support registration.

  • Develop the About Us page.
  • Develop the Services page.
  • Develop the Registration page.
  • Add form validation.

Sprint 10 — Develop Learning Features

Focus: Build the learning activities and supporting pages.

  • Develop the Quiz page.
  • Develop quiz functionality.
  • Develop the Progress page.
  • Develop the Contact page.

Sprint 11 — Style and Integrate the Website

Focus: Improve the appearance and usability of the website.

  • Apply website styling.
  • Make the website responsive.
  • Integrate website components.
  • Perform initial testing.

Sprint 12 — Test Website Functionality

Focus: Check the website features and correct problems.

  • Test website navigation.
  • Test the registration form.
  • Test quiz functionality.
  • Fix identified website bugs.

Sprint 13 — Improve and Document the Website

Focus: Improve the user interface and prepare project documentation.

  • Improve the website user interface.
  • Optimise the website for responsive screens.
  • Prepare final documentation.
  • Review the Agile Logbook.

Sprint 14 — Deploy and Review the Website

Focus: Review project records, integrate work and check the completed website.

  • Review the Trello board.
  • Merge GitHub branches.
  • Deploy the website.
  • Conduct final system testing.

Sprint 15 — Present and Submit the Project

Focus: Prepare the final deliverables and reflect on the project experience.

  • Prepare the final presentation.
  • Present the final project.
  • Submit the final project.
  • Conduct the sprint retrospective.

PERSONAL REFLECTION

What I Learned

Working with the Sprint Backlog taught me how to break a large project into smaller stages. Instead of working from one long list of tasks, we organised the work into sprints on Trello after receiving feedback from the lecturer.

As Product Owner, I helped organise sprint tasks, add dates, follow up on task allocation and remind team members about outstanding work. This helped me understand the importance of planning, communication and monitoring progress throughout a project.

One challenge was that some team members were not consistently available. Connectivity and technical difficulties also sometimes affected our progress. Some tasks and user stories needed further organisation.

I learned that creating sprint boards is only one part of Agile planning. The team must also agree on achievable goals, assign responsibilities clearly, update task statuses and review unfinished work.

In future projects, I would make sure each sprint has a clear goal, tasks have appropriate owners and progress is reviewed regularly. I would also ensure that user stories and task updates are recorded consistently so that the backlog provides a clearer picture of the team's progress.
